# Profile, installer and docs audit — 2026-11-07

Scope: `scripts/lib/*.sh` (generated `claude-proxy*.sh`), `scripts/claude-proxy.ps1`,
`scripts/setup.sh`, `scripts/setup.ps1`, `scripts/build-profiles.py`, `README.md`
and `docs/*.md`, after v2.13.0. Method: reading the risky paths (anything that
writes files the user depends on, parses untrusted data, or kills processes),
scripted doc checks (links, anchors, every command and `CLAUDE_*` key named in
the docs exists), and the portable test suite. ShellCheck/PSScriptAnalyzer
could not be installed on the audit host.

Severity: **High** = security or data loss; **Medium** = wrong behaviour for a
realistic setup; **Low** = robustness or clarity.

| ID | Sev | Area | Finding | Status |
|----|-----|------|---------|--------|
| A1 | High | Nodes (sh, ps1) | Node-catalogue fields (from DNS TXT, a VM, or the guide's JSON) were written to `~/.ssh/config` and `~/.ssh/known_hosts` without validation. A spoofed TXT record could add a second, attacker-controlled host key for a host that already has a pinned key (ssh accepts any listed key), or inject tokens into the ssh config. | Fixed: fields validated; a catalogue host key is added only when `known_hosts` has no key for that host, and a mismatch is reported instead of added. |
| A2 | High | Installer (sh, ps1) | The key from Downloads was copied to `~/.ssh/<same name>` and silently replaced an existing, different private key of the same name (e.g. `id_ed25519`). | Fixed: an existing different key is kept; the new key is installed as `<name>-claude-proxy` (or the identical file is reused). |
| A3 | Medium | Settings sync (sh) | `for f in $(_settings_targets)` split paths on spaces: on WSL with `SYNC_WINDOWS_SETTINGS=1` and a Windows user name containing a space, the proxy was written to wrong paths and never to Windows Claude. | Fixed: line-wise loop, as the kill switch already did. |
| A4 | Medium | Config (sh profile + installer) | `_conf_set` / installer `conf_set` wrote `KEY="value"` without escaping `"`, `$`, `` ` `` or `\`; the file is sourced as shell, so such a value broke every new shell or ran as code. | Fixed: values are escaped for double quotes; newlines are refused. |
| A5 | Medium | Settings sync (sh, ps1) | `settings.json` was written through a temp file in `/tmp` (not atomic across filesystems; replaced a symlinked file with a plain file), and `.bak` was overwritten on every write, losing the pre-proxy copy. | Fixed: temp file next to the target, contents written through the symlink; the first `.bak` (`settings.json.claude-proxy.orig`) is kept. |
| A6 | Medium | Settings sync (ps1) | `Set-Content -Encoding utf8` writes a BOM on Windows PowerShell 5.1; strict JSON readers can reject it. | Fixed: UTF-8 without BOM. |
| A7 | Low | `proxy-update` (sh) | The installed profile was replaced with `cp` (a full disk or interrupted copy leaves a truncated profile that breaks every new shell). | Fixed: write to a temp file beside it, syntax-check, then rename. |
| A8 | Medium | Desktop alerts (ps1) | `New-RecoveryDesktopContext` reported the `windows-tray` backend as ready after its 2 s wait even when the notification thread had failed or never started (Windows without a desktop, e.g. Server Core). `tests/proxy-desktop.ps1` exposed it on every non-Windows host. | Fixed: only a thread that reported ready is a backend; otherwise `unavailable` with the reason (wait up to 5 s). |
| A9 | Low | Docs | README's "Something does not work?" opened with port details before the steps, and neither README nor troubleshooting mentioned `cc-help`, `cc-manual` or shared-mode errors. | Fixed. |
| A10 | High | Test harness | `tests/run.py` ran every test with the developer's real `HOME`; a test (or an ad-hoc preview) that loads a profile pins the proxy into the real `~/.claude/settings.json` and can write `~/.ssh`. | Fixed: each run gets a throwaway `HOME` and XDG folders. |
| A12 | Medium | Installer (ps1) | The key was locked by removing inherited permissions and then granting read access to the bare `$env:USERNAME`, with errors discarded. For Microsoft-account, Entra ID or domain logins the name may not resolve, leaving a key nobody can read (ssh then cannot use it). | Fixed: grant by the current user's SID first, remove inheritance only after the grant succeeded, and warn otherwise. Not exercised on Windows from the audit host. |
| A13 | Low | Test harness | Two tests were too tight or incomplete for the new code: the editor test's 15 s limit (the editor takes ~7 s alone), and the kill-switch fixture's partial loader. | Fixed: 60 s limit; loader includes the new helper. |

Checked and found correct: every `eval` uses fixed variable names; doc links
and anchors resolve (sidebar paths are site-absolute); every command and
`CLAUDE_*` setting named in the docs exists; the kill-switch pin requires both
`KILLSWITCH` on and `SYNC_SETTINGS=1`, as documented; PowerShell settings are
PSD1 data written through an escaping serializer (no A4 equivalent);
`proxy-update` downloads over HTTPS and refuses files that do not parse.

Not verified on this host: native Windows / Windows PowerShell 5.1, macOS
(`netstat` listener detection, Keychain), and a real second macOS account.
